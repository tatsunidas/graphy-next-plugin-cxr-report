# Chest X-ray Report Draft (CXRMate) — GRAPHY-Next plugin

胸部X線 1 枚（CR/DX）から、所見（findings）と印象（impression）の**下書き**を作る GRAPHY-Next の公式プラグインです。
モデルは [CXRMate](https://huggingface.co/aehrc/cxrmate-single-tf)（aehrc・Apache-2.0）。

> ⚠ **研究用です。診断・治療の判断に使わないでください。** 生成された文は誤りを含み、画像にない内容
> （撮影方向・年齢・性別・過去画像との比較など）が入ることがあります。医療機器ではありません。

> **対象は胸部の正面像（PA/AP）の 1 枚だけです。** このプラグインは CR/DX かどうかしか見ず、部位（胸部か）も撮影方向（正面か）も
> 判定しません。膝や腹部、胸部の側面像でも実行はできますが、結果は無意味です。

## 使い方
1. 2D ビューアで胸部X線（CR/DX・1 枚）を開く。
2. 「解析 ＞ AI ＞ Chest X-ray Report Draft」を開き、「実行」を押す。
3. 同意の窓で、送るデータと実行されるコードの全文を確かめて承認する。
4. 所見と印象が表示される（コピーできる。DICOM への保存はしない）。
5. 下の **Grad-CAM** の一覧で文を押すと、その文の生成に効いた領域が画像に重なる（青 = 効いていない → 赤 → 黄 → 白 = 強く効いた。
   不透明度は調整でき、「消す」で外せる）。

## 動く場所と条件
- **この PC の計算機（環境設定 ＞ 外部の計算機の「この PC」）でだけ動きます。** 胸部X線は画素に焼き込まれた文字を
  塗らずに渡すため、本体が外部の計算機（Colab など）への送信を断ります（`dataset-local-only`）。画像は PC の外へ出ません。
- GRAPHY-Next 0.5.1 以降（マスク無しの CR/DX を local にだけ渡す変更を含む版）。
- 計算機の Python に **torch・torchvision・`transformers==4.46.3`**・pillow・numpy。環境は書き換えません。
  **最初の「実行」で、画像を送らない小さな事前チェック（コードだけのジョブ・同意 1 回）が先に走り**、足りないものを表で示し、
  計算機が実際に使う Python を名指しした `pip install` のコマンド（コピーできる）を出します。入れたら［再確認］を押します
  （本体の再起動は要りません）。通ったあとは、その窓のあいだ事前チェックを省きます。🔴 **transformers は 4.46.3 だけ**です（4.57.6 では `generate` が落ちることを確かめた。
  それ以外の版は未確認なので止めます）。
- 重みは同梱しません。初回に Hugging Face から取得します（キャッシュ約 430 MB）。`trust_remote_code=True` で
  モデルの Python コードを読むため、**モデルとコードを固定の revision（`84dfcba8125c9b9296bfc1ee317749788b6b59b4`）で取得**します。
  同意画面のコードに revision が出ます。
- 対象は胸部の正面像（PA/AP）の 1 枚だけ（部位・撮影方向は判定しない）。2D 画像 1 枚だけで、多フレーム・CR/DX 以外（MG を含む）は、理由を出して止まります。
  表示の窓（DICOM の WindowCenter/Width）を当てて 8bit にして渡します。窓が無ければ最小〜最大です。

## Grad-CAM（説明可能性）
- 対象は、エンコーダ（CvT）の最終段の特徴マップ（384×384 入力に対し 24×24）です。生成した文ごとに、その文の対数確率の和を
  特徴マップで微分して作ります（`generate` は勾配を切るので、生成済みの系列で teacher forcing をやり直します）。
- 🔴 **所見が正しいことの根拠ではありません。** 「その文の確率に効いた領域」を示すだけです。画像にない内容
  （年齢・撮影方向・過去画像との比較など）の文には、意味のある領域は出ません。
- 「強さ」は、全文の最大に対する比です。小さい文は画像にほとんど依存していません（文は言語側の定型で決まっている）。
- 解像度は粗く（24×24 を元画像へ双線形で伸ばす）、輪郭は荒いです。正方形でない画像は、前処理で中央の正方形だけを見るため、
  切り落とされた端は透明（見ていない範囲）になります。
- 安全装置: 再計算した確率が生成時の確率（`sequences_scores`）と 0.01 以上ずれたら、別の確率を微分していることになるので
  Grad-CAM は出さず、理由を表示します（レポートは出ます）。
- 実測（NIH ChestX-ray14 の 1 枚・CPU）: 再計算の確率は生成時と一致（差 < 1e-4）。Grad-CAM の追加は 1 枚で 数秒（9 文）。

## 確かめたこと・確かめていないこと
- 確かめた（Linux・CPU・Electron の実機）: NIH ChestX-ray14 の 1 枚（1024×1024）で、所見と印象が返る・同意画面に
  注意と revision が出る・SHA-256 が出る・`transformers` が別の版の環境では理由を出して止まる。CPU 16 コアで 1 枚 約 10 秒（実機・重みはキャッシュ済み・読込を含む。別の直接実行では約 58 秒だった）。
- Grad-CAM の妥当性（1 枚・11 文の試作での測定。**強い裏付けではありません**）:
  - 最大の領域を平均色で隠したときの文の対数確率の低下は、最小の領域を隠した場合より大きい文が 8/11、ランダムな領域に対する順位の平均は
    0.71（偶然なら 0.5）。低下そのものは小さく（最大 0.35）、はっきり効いたのは 2 文だけでした。
    → この画像では、文の多くが画像よりも言語側の定型に依存しています。画面の「強さ」はこれを反映します。
  - 入力を左右反転すると Grad-CAM も反転して出る（11 文すべてで、反転した cam との相関のほうが高い。相関は 0.2〜0.85）。縦横の取り違えは無い。
  - 1 枚だけの測定で、統計的な結論は出せません。
- 確かめた（外部 GPU・Google Colab の Tesla T4）: 計算機の上のコード（モデル実行部）が CUDA で動き、所見・印象・Grad-CAM が返る。
  再計算した確率は生成時と一致し、同じ画像の CPU 実行と**生成文が完全に一致**した。GPU のピークメモリは 1417 MiB、1 件 約 36 秒
  （取得・セットアップ 15 秒を含む）。🔴 ただし本体は胸部X線を外部の計算機へ渡さないので、**画像は送らず**、Colab 側で公開サンプルを取得して
  同じスクリプトを実行する形での確認です（プラグインの実経路ではない）。この確認で、CUDA で Grad-CAM が作れない不具合（0.1.0）が見つかり、0.1.1 で直した。
- **未確認**: この PC の NVIDIA GPU（GTX 1050 Ti・4 GB）での実行、Windows・macOS、初回の重みの取得（検証時はキャッシュ済み）、生成文の臨床的な正しさ。
  実際の出力は「PA and lateral views」「___-year-old female」「Comparison is made with…」のように、1 枚の画像からは
  言えない定型文を含みました。生成文の正確さは評価していません。

## ライセンスと出典
- このプラグインのコード: MIT（`LICENSE`）。

  **学習データは MIMIC-CXR** です。本プラグインは MIMIC-CXR のデータを同梱・使用しません（モデルの重みだけを使います）。
  論文: Nicolson et al., *Longitudinal data and a semantic similarity reward for chest X-ray report generation*,
  Informatics in Medicine Unlocked (2024), doi:10.1016/j.imu.2024.101585。
